## 버림

- `ARTEX-worker/1.0`. `web/src/lib/mock/data.ts:2912` 의 UI 목업이다. 워커의 고정 User-Agent 로 확인되지 않았다. PLURA 5절과 같다. 합성 로그에 이 값을 넣어도 `artex-hunt` 는 항목을 만들지 않는다.
- `/api/`, `/rest/`, `/graphql/`, `/admin/` 등 `API_HINT` 접두사. 분류 정규식의 예이지 항상 요청하는 URL 이 아니다. `harvest_static.py:87`, `spider_mpa.py:24`. 행위 휴리스틱은 건수와 다양성만 보고, 룰 파일에는 경로 서명을 넣지 않았다.
- 공격 IP. PLURA 1보는 구체적 IP 목록을 확보하지 못했다고 밝혔고, 안랩은 호스팅 IP 를 AhnLab TIP 에서 본다고만 했다. 공개된 목록을 검증할 수 없어 넣지 않았다.
- v0.3.14 배포 ZIP 의 SHA-256. PLURA 1보가 다섯 개 값을 릴리스 자산 메타데이터로 소개했다. 2026-10-10 에 Autumn-27 릴리스를 다시 받아 해시하지 못했다(저장소 HTTPS 404, Hinln 릴리스 API 는 비어 있음). 검증하지 못한 해시는 탐지 데이터에 넣지 않았다. PLURA 도 이 값을 악성파일 해시가 아니라고 밝혔다.
- User-Agent 부재. PLURA 랩에서 관찰된 특징이지만 정상 클라이언트도 헤더를 빼므로 단독 지표로 쓰지 않는다.
- 컨테이너 이름만 `artex` 인 경우. 이미지 이름이 아니면 올리지 않는다. 합성 표본의 `ubuntu` 컨테이너가 이름만 `artex` 인 경우를 테스트로 고정했다.

## 사건과의 거리

세 User-Agent 는 소스에 있다. 그 사실이 2026년 10월 금융권 조사에서 이 문자열이 보였다는 뜻은 아니다. PLURA 가 그 차이를 명시했다. 안랩 ASEC 은 10월 1일 분석과 이후 추적에서 노출 콘솔과 주변 도구를 집계했고, 발견만으로 악성 판단을 하지 말라고 했다. 이 저장소의 신뢰도 "높음" 은 "소스에서 이 문자열이 그 용도로 박혀 있다"는 뜻이다. "이 요청이 그 사건의 공격이다"가 아니다.
