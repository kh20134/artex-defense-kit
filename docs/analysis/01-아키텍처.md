# ARTEX 구조, 방어자가 볼 범위

분석 기준은 Hinln/ARTEX 커밋 `f3e3f54` (2026-10-08)이다. changelog 에 v0.3.14 를 못 박은 커밋 `86162d7` (2026-09-24)에서도 아래에 인용한 식별 문자열을 다시 확인했다. Autumn-27/ARTEX 는 2026-10-10 공개 HTTPS 조회에서 404 였다. PLURA 1보가 분석 기준으로 밝힌 버전은 v0.3.14 이다.

이 글은 플래너와 워커가 어떻게 나뉘고, 그 결과가 네트워크와 호스트에 무엇을 남기는지만 다룬다. 공격 절차, 페이로드, 우회 설정은 적지 않는다.

## 한 줄 요약

ARTEX 는 Go 백엔드 하나에 Next.js 화면을 넣고, PostgreSQL 에 자산 그래프와 탐색 그래프를 쌓는 LLM 다중 에이전트 프로그램이다. 작업이 시작되면 플래너 루프 하나와 워커 루프 N개가 돈다. N 의 기본값은 3이다. 워커가 도구를 실행하고, 결과가 그래프에 다시 쓰이면 플래너가 다음 의도를 낸다.

출처: `server/engine.go` 의 `Run` (745행 부근)이 `plannerLoop`(800행) 하나와 `workerLoop`(916행) N개를 띄운다. `server/manager.go` 284행 `defaultWorkers = 3`. 화면의 LLM 형식은 `openai`, `anthropic`, `openai-responses` 이다 (`web/src/lib/types.ts` 1029행). DeepSeek 은 목업 프로필(`web/src/lib/mock/data.ts` 3029행, base URL `https://api.deepseek.com`)과 웹 검색 백엔드 이름(`server/manager.go` 280–282행)으로 소스에 있다.

안랩이 2026년 10월에 공개한 후속 글은, 인터넷에서 본 ARTEX v2 화면이 중앙 플래너와 여러 워커, 작업 공간, MCP, 재사용 스킬을 보여 주었다고 적었다. 그 글은 노출된 콘솔의 수를 집계했을 뿐, 금융권 사건의 사용을 확정하지 않았다.

## 방어자가 구분할 네 층

| 층 | 하는 일 | 밖에서 보이는 것 |
| --- | --- | --- |
| 콘솔 | 브라우저로 작업을 보고 토큰을 저장 | 제목 문자열, `artex_token` 키, 기본 포트 8787 |
| 엔진 | 플래너 1 + 워커 N | 프로세스 이름 `artex`, 환경 변수 `ARTEX_*` |
| 고정 수집 코드 | HTTP GET 에 박힌 User-Agent | 아래 세 문자열. 모든 요청을 대표하지 않음 |
| LLM 이 만든 도구 호출 | 모델이 고른 HTTP 클라이언트 | User-Agent 가 없을 수 있음 |

도구 실행 자체는 콘솔 안의 기록이 된다. 피해 웹 로그에는 "Bash" 나 "planner" 같은 이름이 남지 않는다. 남는 것은 HTTP 요청과, 설치한 호스트의 파일·프로세스·컨테이너이다.

## 고정 수집 모듈

`enrich` 는 자산 URL 에 GET 을 보내고 User-Agent 를 `artex-enrich/1.0` 으로 둔다. 본문은 1MiB 에서 자른 뒤 상태 코드와 title 을 저장한다 (`enrich/enrich.go` 224–248행, User-Agent 는 233행).

`skills/api-recon/scripts/harvest_static.py` 는 진입 HTML 에서 스크립트 주소를 모은 다음 JS 를 병렬로 받는다. User-Agent 는 23행의 `Mozilla/5.0 (spa-api-recon)` 이다. 스레드 풀 크기는 145행이 20, 163행과 174행이 24이고, 청크를 따라가는 반복은 151행에서 6회로 막혀 있다.

`skills/api-recon/scripts/spider_mpa.py` 는 SPA 번들이 없을 때 HTML 을 같은 출처에서 순회한다. User-Agent 는 22행의 `Mozilla/5.0 (spa-api-recon spider)` 이다. 기본 인자는 최대 200페이지, 깊이 4, 지연 0.1초(70–71행)이다. `.js` 등 정적 확장자는 순회에서 건너뛴다(23행). 0.1초와 200, 4 는 스크립트 기본값이다. PLURA 도 이 값을 사건에서 측정된 속도라고 쓰지 말라고 했다.

두 스크립트의 `API_HINT` (`harvest_static.py` 87행, `spider_mpa.py` 24행)는 HTML·JS 문자열을 API 후보로 나누는 정규식이다. `/api/`, `/graphql/` 같은 접두사를 ARTEX 전용 URL 로 보면 안 된다.

`skills/api-recon/scripts/runtime_harvest.js` 는 puppeteer-core 로 시스템 Chromium 을 띄운다(머리말 14행, `require` 40행, chromium 경로 46행). 이 경로는 위의 고정 User-Agent 를 쓰지 않는다. 브라우저가 만든 요청으로 남는다. 인증을 다루는 내부 동작은 여기 적지 않는다.

## 업데이트와 콘솔

업데이트 클라이언트는 GitHub 릴리스를 조회·다운로드하면서 User-Agent `artex-selfupdate` 를 붙인다 (`selfupdate/github.go` 129행, `selfupdate/stage.go` 227행). v0.3.14 커밋에서는 github.go 97행이다. 허용 호스트는 GitHub 관련 이름이다. GitHub 를 공격자 도메인으로 분류하지 않는다.

콘솔 토큰 키는 `artex_token` 이다 (`web/src/lib/auth.ts` 1행). 서버는 쿠키 이름으로 같은 문자열을 읽는다 (`server/auth.go` 112행. v0.3.14 는 89행). 피해 사이트로 나가는 고정 쿠키가 아니다.

화면 제목은 `ARTEX — 自主渗透测试控制台`, 설명은 `LLM 驱动的自主渗透测试系统控制台` 이다 (`web/src/config/app-config.ts` 10–11행).

Compose 이미지 이름은 `autumn27/artex` 이다 (`docker-compose.yml` 18행). 포트 8787 은 UI·API, 8788 은 기록 프록시이고 Compose 는 8788 을 루프백에만 매핑한다(32–33행. v0.3.14 는 31–32행). 포트 번호만으로 판정하지 않는다.

## UI 목업에만 있는 문자열

`web/src/lib/mock/data.ts` 2912행의 `ARTEX-worker/1.0` 은 화면용 가짜 트래픽이다. 워커 루프에는 이 문자열이 없다. 탐지 룰에 넣지 않는다. PLURA 1보 5절과 같다.
