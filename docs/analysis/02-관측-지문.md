# 네트워크·호스트에서 보이는 것

지표의 기계가 읽을 원본은 `src/artex_hunt/data/indicators.yaml` 이다. 여기에는 그 값을 로그와 호스트 어디에서 봐야 하는지만 적는다.

## 들어오는 HTTP

웹 서버, WAF, 리버스 프록시, API 게이트웨이처럼 User-Agent 가 남는 로그에서 다음 세 값을 **전체 문자열**로 본다.

| 값 | 소스에서 하는 일 | 로그에서 기대하는 모양 |
| --- | --- | --- |
| `artex-enrich/1.0` | 자산 URL GET | 소수의 GET. 본문 상한 1MiB 는 서버 로그에 직접 안 남는다 |
| `Mozilla/5.0 (spa-api-recon)` | HTML 다음 JS 병렬 수집 | 짧은 시간에 서로 다른 `.js` 가 많이 찍힐 수 있다 |
| `Mozilla/5.0 (spa-api-recon spider)` | HTML 순회 | 정적 확장자는 건너뛰므로 HTML 성 경로가 잇따른다 |

대소문자는 소스에 소문자·혼합으로 박혀 있다. 로그 장비가 대소를 바꿀 수 있어 헌트 도구는 전체를 대소문자 무시로 비교한다. 문자열이 포함되기만 하면 중간 또는 낮은 신뢰로 내린다.

이 셋은 ARTEX 의 모든 요청이 아니다.

- PLURA 가 2026-10-09 에 공개한 승인 랩에서는 LLM 이 `http.client` 로 만든 GET 8건에 User-Agent 헤더가 없었다. `spa-api-recon` 정확 일치는 0/8 이었다.
- `runtime_harvest.js` 는 Chromium 을 띄우므로 브라우저 User-Agent 가 된다.

그래서 세 문자열이 없다고 조사를 끝내지 않는다. 문자열이 있다고 침해 성공도 아니다. PLURA 1보는 금융권 공격 로그와 이 값을 대조하지 않았다고 밝혔다.

## 나가는 HTTP

`artex-selfupdate` 는 설치본이 GitHub 릴리스를 볼 때 붙인다. 포워드 프록시·아웃바운드 게이트웨이 로그의 후보다. 피해 사이트의 WAF 룰에 넣지 않는다. 목적지 도메인을 악성으로 보면 안 된다.

## 호스트

비인가 설치를 볼 때 아래를 같이 본다.

- 컨테이너 이미지 `autumn27/artex`
- 콘솔 HTML 의 제목·설명 문자열
- 프론트 코드의 `artex_token` 키. 피해 사이트 쿠키 차단 규칙으로 옮기지 않는다
- 파일 또는 프로세스 이름이 `artex` / `artex.exe`. `artex-hunt` 는 제외한다
- 경로 `skills/api-recon/scripts/harvest_static.py`, `spider_mpa.py`
- 락 파일 이름 `spa-api-recon-runtime`
- 프로세스 환경의 `ARTEX_PG_DSN`, `ARTEX_UPDATE_GITHUB_TOKEN`. 값은 보고서에 남기지 않는다

8787/tcp 와 8788/tcp 는 기본 구성 메모이다. 헌트 도구는 이 포트만으로 항목을 만들지 않는다. 8788 이 밖에 닫혀 있어도 설치가 아니라고 할 수 없다. Compose 가 루프백에만 열기 때문이다.

## 행위 휴리스틱

`artex-hunt` 의 낮은 신뢰 항목은 시그니처가 아니다. 임계값 기본값은 사건 관측값이 아니다.

| 항목 | 기본 임계 | 근거로 삼은 사실 | 오탐 |
| --- | --- | --- | --- |
| JS 다양성 | 60초 안 서로 다른 `.js` 20개 | 수집 스크립트의 병렬 수신(풀 20·24) | 큰 SPA 첫 로딩 |
| API 경로 다양성 | 60초 안 API 처럼 보이는 경로 25종 | PLURA 가 권한·반복 조회를 같이 보라고 한 조사 방향. 경로 자체는 지표가 아님 | 정상 SPA, BFF |
| 조회 값 변경 | 같은 경로에서 조회 파라미터 8종 | 같은 글의 "파라미터를 반복해서 바꾼다" | 검색창, 페이지네이션 |
| HTML 몰림 | 20요청, 고유 경로 15, 요청당 0.05–0.40초로 환산한 구간 | 순회 스크립트 기본 지연 0.1초. 초 단위 로그에서도 보게 구간 길이로 환산 | 링크 검사기 |

검증된 User-Agent 가 같은 출발지에 있으면 JS·API·조회·순회 항목은 중간 신뢰로 올린다. 높아지지는 않는다. User-Agent 항목이 이미 높다.

임계값은 CLI 와 지표 파일에서 바꾼다. 사이트 트래픽에 맞게 올려 쓰는 것이 기본 자세이다.
